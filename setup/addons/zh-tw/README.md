# 繁體中文（台灣）在地化選配包

> 只有在作者用**繁體中文、寫給台灣讀者**時才需要。其他語言完全略過這個資料夾。
> 這裡說明三種檢查「該做什麼、為什麼」；對應的**現成工具已附在 `tools/zh-tw/`**
> （純 Python 標準庫、零安裝，直接可跑），見 `tools/README.md`。lite 模式下 Claude
> 也可手動執行同樣的判斷。

## 現成工具（`tools/zh-tw/`，零安裝）
- `zh_localize.py` → 下方第 1 點（陸用語 + 台/臺）
- `zh_ai_style.py` → 下方第 3 點（中文 AI 句法指紋；`--authored` 指向你自己的稿可更準）＋第 4 點的
  對比句總量與 120 字以上長句清單
- `voice_lint.py` → 你的聲音硬規則閘門（配 `templates/voice_rules.template.json` 自訂）；也掃句型標題、
  八股套語，並列出 AI 套話候選供人判；論文、計畫書、申請書加 `--paper`（見下方「語域」一節）
- `zh_register.py` → 稿件的語域輪廓（52 項特徵）對照同場域台灣期刊論文，見下方「語域」一節
- `zh_gloss_scan.py` → 第 4 點的括號夾註盤點（術語首現該怎麼處理）
- 子代理範本 `agents/zh-tw-native-editor.md` → 台灣學術中文母語潤稿（本選配包的一部分，只交改動清單），
  搭配 `tools/register/register_profile.py` 與 `tools/register/polish_check.py`
- 選配：**zh-metadiscourse-scale**，一份量表，不是判定器，用來對照中文後設論述標記（值得注意的是／
  本研究認為…之類）夠不夠自然，不是拿它當通過／不通過的門檻；讀它自己的說明文件再決定怎麼用。

## 這個選配包加了什麼

繁中學術寫作有三個英文工具鏈照顧不到的層面，co-author / paper-review 在繁中模式要多跑：

1. **台灣慣用語檢查（陸用語 + 台/臺）**
   - 抓大陸用語（如「反饋 → 回饋」「軟件 → 軟體」「視頻 → 影片」「數據 →（視語境）資料/數據」），
     以及「台/臺」全篇一致。
   - 需要一份**誤判白名單**（有些詞在語境下是對的），避免機械式替換。
   - lite：Claude 依常見對照表逐項判斷並附引句；full：本機批次腳本掃全篇。

2. **官方術語譯名一致性**
   - 專有名詞、技術術語的中譯是否對齊**官方/權威譯名**（台灣有國家教育研究院樂詞網等權威來源），
     全篇同一概念用同一譯名。
   - 格式多為「中文（English）」夾注；掃全篇這種對照、標出不一致或非官方譯法。
   - lite：Claude 查權威譯名逐詞核對；full：本機比對官方譯名庫。

3. **中文 AI 句法指紋（去 AI 味，中文校準）**
   - 英文的 AI-tic 偵測搬到中文要重新校準：以漢字為分母算破折號／分號密度、三連並列密度、
     句長變異，並抓中文趨同詞（如「構成／正是／值得注意的是／不僅…更／進一步／彰顯／凸顯／
     賦予／誠然／某種程度上／換言之／旨在／致力於」）。
   - 🔴 保留「做概念工作」的修辭（對偶、論點收尾、嵌入問句），只動純插入語；同一稿**改前／改後
     比較最準**（中文缺乾淨基線時用啟發式門檻）。
   - 🔴 另一層人眼才看得到的「像 AI 潤過」的味道（三連當副歌、格言式段末、自我評價式收尾判語），
     統計指紋抓不到，交付前要另派一輪乾淨視角挑句。

4. **中文學術語體四條（工具會量，判斷仍是人的）**
   來源是一次真實回饋：一份計畫書所有工具都過了，資深合著者仍評「用字用詞語法不夠學術、
   圖表太少字太多」。整理成四條，交稿前逐條看：
   - **小節標題一律名詞短語**：不寫完整句、不寫疑問句，章內小節不與章名同義反覆。
     `voice_lint.py` 會掃 Markdown `#` 與 Typst `=` 標題行。
   - **對比句只留承重對比**（並非…而是＋而非＋而不是＋不在於…而在於＋與其…不如，全部合計算一個
     總量），其餘改直陳。`zh_ai_style.py` 報每千字總量，**同文類真人論文參考值：中位數約 0.10、
     p90 約 0.40**，超過就逐句檢視（實測一份 2.3 萬字稿有 20 處，被點名）。🔴 每一輪修稿後都要
     重量一次，不是只在交稿前量；**不准把其中一種對比形狀換成另一種**（「並非…而是」換成
     「而非」，總量不會因此下降，兩者都算在同一個總量裡）。
   - **超過 120 字的句子拆**，並列清單（頓號三個以上）除外。`zh_ai_style.py` 逐句列出。
   - **術語首現三選一**：就地一句定義／括號英文對照／指路至完整說明。註解用定義句、不用口語
     （「缺誰就少誰」→ 定義句），**不集中成術語表**（不好讀）。`zh_gloss_scan.py` 列出 12 字以上
     的括號夾註供人判：白話註解改定義句、規格清單可留、純贅述刪。
   - 同一次回饋的排版面：內容與總覽圖重複的表併入圖；拆圖拆表前先列出回歸規則釘在該圖表上的字串，
     逐條決定去處；頁數卡住時的診斷見 `skills/build-pdf/SKILL.md`。

## 語域：論文照期刊，信件才照作者的聲音

論文、補助計畫書、申請書以**同場域台灣期刊論文的語域**為準繩，不套作者的個人聲音。「像台灣學者寫的」
在這裡定義成：稿件各項語域特徵落在同場域已發表論文的 p10–p90 區間內，目標是區間，不是中位數。
台灣期刊論文常用「進行」「透過」「具有」「針對」、分號與書面語的「之」，句子也比機器改寫長；照規範派
規則把這些改光，反而會把稿子推離期刊。

- **量測**：`tools/zh-tw/zh_register.py`（52 項特徵：自稱、翻譯腔、連接、後設論述、立場、標點、句長）。
  語料由作者自備：至少 30 篇他人已發表的同領域論文（最好是 2023 年以前），轉成純文字放在
  `<語料>/<期刊>/*.txt`，每篇正文 1000 字以上；同一本期刊湊滿 30 篇，就能單獨對照該刊。掃描版 PDF
  先做文字辨識（MinerU）。語料路徑記在作者的 CLAUDE.md（`ZH_CORPUS_DIR`）。作者自己的稿永遠不放進去。
- **偏離清單**：`tools/register/register_profile.py <稿> --lang zh --corpus <語料> --venue <期刊>`，
  分成要修、鎖定、交作者決定、在區間內四類，並給每一段的合理次數範圍。
- **母語潤稿**：`agents/zh-tw-native-editor.md` 只交改動清單，由主對話逐條裁定；
  `tools/register/polish_check.py` 自我檢查數字與引用有無變動、字數預算、禁用形式與語域方向，全部通過才能用 `--apply`
  寫回。流程見 `method/WORKFLOW.md` Phase 5.5。
- **voice_lint 的論文模式**：論文、計畫書、申請書加 `--paper`。分號與乃／則是／抑或這類台灣期刊常用、
  只是作者個人不用的寫法不擋；綜上所述、整體而言改成只列不計（也別新增）；破折號、這一／此一、口語、
  然而起句、自評飾詞照擋。
- **lite（沒有語料或沒有 Python）**：讀目標期刊的投稿須知，加上作者提供或指定的 2–3 篇該刊論文，
  逐項比對自稱（本研究／本文）、句長與連接方式、翻譯腔、標點，手寫一份偏離清單，並註明這是閱讀比對、
  不是量測。

`VOICE_PROFILE` 只用在信件、自傳、個人陳述這類讀者期待看到作者本人的文字。
🔴 常見 AI 壞習慣：擅自加「此即本作的賭注／恰恰是…價值所在／真正的…在於」這類**自我吹捧收尾判語**。
擴寫只陳述事實與論證，**判語留給作者**。

## 繁中 PDF 排版配方（Typst；接 `build-pdf` skill 的「非 LaTeX 路徑」）

繁中稿走 LaTeX 常卡在 CJK 套件（`xeCJK`/`ctex`）裝不上或裝不全；Typst 對 CJK 與系統字型開箱即用，
是成本最低的一條路（純本機、無遙測，排版時稿件不會送出去）。`.typ` 檔頭用這組當預設：

```typ
#set text(
  font: ("Noto Serif CJK TC", "Noto Sans CJK TC"),   // 可攜：任何平台裝 Noto CJK 即可
  size: 11pt, lang: "zh", region: "tw",              // 台灣斷行與標點習慣
)
#set par(justify: true, leading: 0.85em)
#set page(paper: "a4", margin: 2.2cm, numbering: "1")
#set heading(numbering: "1.1")   // 不要編號就刪這行

// 正文：= 一級標題 / == 二級 / + 條列 / *粗體* / _斜體_
// 圖片：#figure(image("figures/x.png", width: 80%), caption: [圖說])
// 表格：#table(columns: 2, [a],[b], [c],[d])
```

- **字型 fallback 要寫成清單**：第一個字型缺字就往後找；系統若有襯線 CJK 字型（macOS 的
  Songti TC／PingFang TC、Windows 的微軟正黑體…）可放在 Noto 前面，但**清單裡一定留 Noto CJK**，
  換機或在伺服器上才產得出同一份 PDF（Linux 裝 `fonts-noto-cjk`；要彩色 emoji 另裝
  `fonts-noto-color-emoji`）。`lang:"zh", region:"tw"` 不可省，否則標點與斷行會走簡中或日文習慣。
- **有圖一定帶 `--root`**：`typst compile --root <專案根目錄> doc.typ out.pdf`，相對路徑才解析得到；
  沒圖可省。邊改邊看用 `typst watch`。
- **從 Markdown 轉**：`#`→`=`、`-`→`+`、`**x**`→`*x*`、`![](p)`→`#figure(image("p"))`，其餘照搬；
  標題層級與圖片路徑逐一核對（最常出錯處）。
- **目檢清單（交付前必看 PDF）**：① 中文無豆腐字（缺字型的方塊）② emoji 有色、沒變成方塊
  ③ 每張圖都有出來、沒被裁掉 ④ 頁碼與斷行正常、中英混排無怪異間距。回報固定含：來源檔、
  字型、頁數、輸出路徑。

## 繁中範本：方法決策／分析計畫／文獻矩陣

`templates/` 下的 `method-decision.template.md`、`analysis-plan.template.md`、
`literature-matrix.template.md` 是英文範本；**繁中版放在
`setup/addons/zh-tw/templates/`**（`method-decision.zh-TW.md`、
`analysis-plan.zh-TW.md`、`literature-matrix.zh-TW.md`）。用繁中寫作時填繁中版，
兩支檢查程式（`tools/method/method_decision_check.py`、
`tools/method/analysis_plan_check.py`）都認得中英文兩種範本的標題與欄位名，不用
另外轉換。
